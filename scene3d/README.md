# 场景演示（三维）

网页里“场景演示”模式的源码：人拿着手机的四种典型场景，讲解视角与人眼视角来回切换，
屏幕按实测数据显示观看者眼睛实际看到的亮度和色偏。

| 场景 | 内容 | 可调（“调整”面板） |
|---|---|---|
| 正视 | 手机举在眼睛正前方，屏幕正对眼睛，作为基准 | 观看距离、手机转开角度 |
| 正常手持 | 坐着单手拿手机，30 cm，微微低头 | 观看距离、手机转开角度 |
| 放在桌上 | 手机平放在桌面，人坐在桌前低头看（默认中心离轴 34°，眼睛高出屏幕约 43 cm） | 离轴角 |
| 地铁旁座 | 你在长椅上正常看手机，右边乘客从侧面斜看（默认 54°）；角落小窗是另一个人看到的同一块屏幕 | 旁人离轴角 |

- 切到“地铁旁座”时，过渡结束会自动进入**旁人视角**（演示重点是屏幕效果）；工具栏里可在“讲解视角 / 旁人视角 / 你的视角”之间切换，换人时镜头从一个人的眼睛平滑移到另一个人的眼睛。
- “防窥”开关用的是小米“开启防窥”那组实测数据（iPhone 是“贴防窥膜”那组）。
- 场景切换约 1.3 秒，人物姿势、手机、道具、镜头一起过渡；结束后人物淡到半透明，焦点回到屏幕。手臂够不到时整个人淡化并提示。
- 快捷键：`1`–`4` 切场景，`V` 切视角，`P` 防窥，`H` 隐藏全部界面（录屏用，保留小窗）。

构建结果是两个普通脚本，放在仓库的 `web/` 里，由 `web/index.html` 加载：

- `web/scene3d.js`：三维场景（three.js 打包在内）
- `web/scene3d-person.js`：人物模型（内嵌，直接双击 `index.html` 也能用）

## 开发与构建

```bash
cd scene3d
npm install
npm run dev          # 独立开发页 http://127.0.0.1:5199/
npm run build:web    # 打包到 ../web/scene3d.js 与 ../web/scene3d-person.js
```

开发页支持网址参数：`?scene=front|normal|desk|subway`、`?view=eye`、`?viewer=nb|you`、`?privacy=1`、`?pattern=white|read|checker|gray`、
`?seek=0.5`（讲解 → 人眼过渡进度）、`?from=normal&scene=desk&p=0.5`（场景过渡停在某进度，截过渡帧用）、`?param.theta=60`。
截图自查：`node tools/shot.mjs jobs.json`；交互流程自查：`node tools/flow.mjs <输出目录>`（无头 Chromium，软件 WebGL）。

## 哪些是实测，哪些是示意

| 内容 | 性质 |
|---|---|
| 屏幕每个像素的亮度变化与色偏 | **实测**：`web/data.js` + 光学模型（`src/optics/model.ts`，由 `web/model.js` 移植，数学不变） |
| 讲解标签里的离轴角、亮度、色偏 | **实测**，按两眼中点到屏幕顶 / 中 / 底的实际角度计算 |
| 无实测的两个方位象限（左上、右下） | 用上下镜像（ψ → −ψ）补全 |
| 离轴角超过 70° | 按 70° 计，标签标“超出实测范围” |
| 人物、手机外观、灯光、背屏画面 | 示意 |
| 屏幕玻璃反光 | 示意，默认关闭（着色器里 `uGlare`） |

屏幕用自定义着色器：不受光照、不做色调映射、不进后期。验收：正视纯白屏时屏幕中心像素是 255 白（已验证）。

## 人物

Quaternius Universal Base Characters（CC0）免费版的男性模型，自带含手指的骨骼。
去掉了贴图、头发、眼球和眉毛，运行时按骨骼收细四肢与肩颈、平滑肌肉与面部细节，做成普通身材的中性人台；
半透明显示时先写深度再画颜色，只显示最外层表面。来源与许可见 `CREDITS.md`。

握持：拇指搭在右边框外侧，四指从背面绕到左边框，小指托在底边。
`s3d.occlusion()`（开发页控制台）会从你的眼睛位置检查有没有身体部位挡在屏幕显示区前面，四个场景都是 0。

## 数据的已知问题

- 30° 与 60° 两组测量时屏幕状态和另外两组不同（0° 亮度高约 25–35%，白点约 5800 K 对 6600 K）。模型按每组自己的 0° 归一化来消除这个差异。
- 看到的效果也受观看者自己显示器的限制（色域、最大亮度、校准）。

## 待确认

1. 小米外观里的估计值（圆角、模组与镜头位置、按键位置）是否需要按实机再量。
2. 数据的方向约定：0° 为手机竖放；面内旋转按“30° 是顺时针”处理；+θ 表示观察者在手机右侧（上下镜像补全后，顺 / 逆时针的约定不再影响结果，但左右约定仍会影响）。
3. 小米“普通”那组数据测量时防窥确实是关闭的（现在另有一组“开启防窥”的数据）。
4. iPhone 数据标的是“GH3”屏，场景里是否就用这组。
