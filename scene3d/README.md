# 场景演示（三维）

网页里“场景演示”模式的源码：人拿着手机的四种典型场景，讲解视角与人眼视角来回切换，
屏幕按实测数据显示观看者眼睛实际看到的亮度和色偏。

| 场景 | 内容 | 可调（“调整”面板） |
|---|---|---|
| 正视 | 手机举在眼睛正前方，屏幕正对眼睛，作为基准 | 观看距离、手机转开、手机俯仰 |
| 正常手持 | 坐着单手拿手机，30 cm，微微低头；手机比正对视线多往后仰 18°（屏幕中心离轴角 18°），和正视对比 | 观看距离、手机转开、手机俯仰 |
| 放在桌上 | 手机平放在桌面，人坐在桌前低头看（默认中心离轴 34°，眼睛高出屏幕约 43 cm） | 离轴角、在桌上转动 |
| 地铁旁座 | 你在长椅上正常看手机（和正常手持一样后仰 18°，你看屏幕中心 18°），右边乘客从侧面斜看（默认约 57°）；右侧两个小窗分别是旁人看到的和你看到的同一块屏幕（讲解视角、人眼视角都显示，方便直接对比） | 旁人离轴角 |

- **换场景时视角沿用**：在人眼视角里换场景，镜头一直留在眼睛里跟着过渡；双眼视差也保持当前的显示方式（并排 / 叠加…），不重播；讲解视角换到新场景的取景。地铁场景的人眼视角默认是**旁人视角**，可在“旁人视角 / 你的视角”之间切换，换人（包括进出地铁场景）时镜头从一个人的眼睛平滑移到另一个人的眼睛。
- **换机型**只换手机：手和手机按新尺寸直接摆好，不重播场景过渡，视角不变。
- **拖动手机调整角度**：讲解视角里按住手机拖动（按在别处仍是转镜头）；人眼视角、双眼视差里在画面任何地方拖动。正视 / 正常手持：左右拖 = 手机转开，上下拖 = 手机俯仰；放在桌上：上下拖 = 离轴角，左右拖 = 在桌上转动；地铁旁座：左右拖 = 旁人离轴角。和“调整”面板的滑块是同一组参数。
- 机型：小米 18 Pro Max / iPhone 18 Pro Max，各用自己的实测数据（iPhone 为 GH3 屏那组）。“防窥”开关：小米是“开启防窥”那组，iPhone 是“贴防窥膜”那组。
- 数据面板（工具栏“数据”或 `D`）：观看方向盘（各方向的实测亮度 / 色偏热力图，圆点是当前观看者，地铁场景两个人都标）+ 沿当前方向的亮度、色偏曲线（有防窥数据时开 / 关两条对比）。绘图沿用屏幕仿真模式的 `web/viz.js`。
- 场景切换约 1.3 秒，人物姿势、手机、道具、镜头一起过渡；结束后人物淡到半透明，焦点回到屏幕。讲解视角里的视线、观看距离、离轴角 / 亮度 / 色偏标注在过渡结束（或拖动手机松手）约 2.6 秒后自动淡出，不挡住观察；再换场景、拖动手机或回到讲解视角时重新出现。
- **人眼视角**：镜头在两眼中点，左右对准手机、画面保持水平（不跟头的左右偏转和歪斜），上下用头的俯仰；视场固定（横屏竖直 46°、竖屏 58°），所以手机在视野里的位置和大小随姿势、距离变化——正视时手机在正前方，正常手持时在视野偏下，放在桌上时更小更远。人眼视角 / 双眼视差里换场景时人物保持半透明，不会先变实心再变透明。换场景过渡中，手机两头都拿在手里时（正视、正常手持、地铁之间）手机跟着手走，手和手机中途不会分开。
- 手机举得高 / 远、伸直手臂也差一点时，肩膀会自动往手机方向带一点（只动锁骨，头和眼睛不动）；仍然够不到时人物淡化（不再显示文字提示）。界面上不放解说文字，只保留读数。
- **双眼视差**（工具栏“双眼视差”或 `B`）：镜头先进入人眼视角，画面一开始就是人眼看到的整体画面，随后从正中间分开成左右两半，两半各自滑开、变成左眼 / 右眼完整看到的画面——两眼相距一个瞳距（默认 63 mm，可调 54–72 mm），都注视屏幕中心，各自按自己的位置查实测数据着色；并排时标出各自的离轴角、亮度、色偏，再滑回中间叠在一起（各 50%）——叠在一起时模拟大脑的融合：两眼都注视屏幕中心，错位被拉回大半（保留约 1/4 的视差），所以屏幕中心完全对齐，越往边缘（和屏幕中心不在同一深度的地方，如放在桌上时屏幕的上下两头、手和背景）越能看出轻微的不重合；两只眼睛共用同一个“上”方向，不会因为低头看手机而互相歪斜。屏幕颜色仍按各自眼睛的位置算，并按**双眼累加**放大色偏：两眼各自的色偏按平方和合成（两眼一样时约为单眼的 1.4 倍，两眼角度不同时偏得多的那只眼占主导），所以叠在一起比只用一只眼（或两眼中点）看更容易看出偏色；亮度不放大。左右交替时每次只看一只眼，不放大。结束后可在“并排 / 叠加 / 左右交替”之间切换、重播；“退出”时合回一个整体再回到人眼视角。双眼视差里同样可以拖动画面调整手机角度。下方列出两条视线夹角、两眼屏幕中心离轴角、亮度差、两眼色差 ΔE00（含亮度）、色度差 Δu′v′，以及双眼叠加后的色偏（和只从两眼中点看的色偏对比）。叠加只是示意，不代表大脑实际融合的结果。
- **大屏幕**：标注、读数、工具栏随窗口大小自动放大（约 1366×820 为 1 倍，1080p 约 1.3 倍，1440p 约 1.75 倍，4K 约 2.6 倍），视线和角度弧的线宽也一起变粗；“调整”面板里的“界面与标注大小”或 `+` / `-` 可以再手动放大缩小（`0` 复原，设置存在本机浏览器）。
- **编排、自动播放与导出视频**：工具栏“编排”打开时间线（工具栏上方一条），由若干段组成，每段是一个场景，后面跟着这一段里依次展示的视角 / 机型（例如 正常手持：讲解视角 → 人眼视角 → 双眼视差）。从下方工具栏把场景、视角、机型按钮**拖上来插入**（场景 = 新的一段，视角 / 机型 = 插到某段里的某个位置；“防窥”开关拖上来插入的是它当前的状态，先拨到想要的“开 / 关”再拖），时间线里的按钮**左右拖动排序**（场景按钮带着整段移动），**拖出时间线删除**，点一下跳到那一步；触屏先长按再拖。工具栏按钮点一下仍然是直接切换。“▶ 播放”按时间线播放：每段先换场景（和这一段的第一个视角同时开始），再依次换视角 / 机型，每一步等动画走完再停留几秒（“调整”面板里设，默认 2.5 秒）。播放中点时间线上的任意一步，就从那一步接着往下播；点工具栏上的场景 / 视角 / 机型按钮，如果时间线里有对应的一步也会跳过去接着播。只有点“■ 停止”（或按空格 / Esc）才停。播放时每段开始会把这个场景的参数恢复默认（忽略手动调过 / 拖过的距离、角度）。“● 导出”把同样的播放录成视频（浏览器会询问共享哪个标签页，选“此标签页”；录制时自动隐藏工具栏、时间线和鼠标，结束后下载 MP4，不支持 MP4 的浏览器为 WebM）。时间线存在本机浏览器里。
- 快捷键：`1`–`4` 切场景，`V` 切视角，`B` 双眼视差，`空格` 播放 / 停止，`Esc` 停止播放或录制，`P` 防窥，`D` 数据面板，`+` / `-` / `0` 界面大小，`H` 隐藏全部界面（录屏用，保留小窗）。
- “调整”面板里还有机身颜色。

构建结果是两个普通脚本，放在仓库的 `web/` 里，由 `web/index.html` 加载：

- `web/scene3d.js`：三维场景（three.js 打包在内）
- `web/scene3d-person.js`：人物模型（内嵌，直接双击 `index.html` 也能用）

## 开发与构建

```bash
cd scene3d
npm install
npm run dev          # 独立开发页 http://127.0.0.1:5199/
npm run build:web    # 打包到 ../web/scene3d.js 与 ../web/scene3d-person.js
```

开发页支持网址参数：`?scene=front|normal|desk|subway`、`?view=eye`、`?view=stereo`（双眼视差；`&st=毫秒` 停在自动播放的某一刻，`&stl=split|overlay|wiggle` 直接切到某种显示）、`?viewer=nb|you`、`?privacy=1`、`?pattern=white|read|checker|gray`、
`?seek=0.5`（讲解 → 人眼过渡进度）、`?from=normal&scene=desk&p=0.5`（场景过渡停在某进度，截过渡帧用）、`?param.theta=60`。
截图自查：`node tools/shot.mjs jobs.json`；交互流程自查：`node tools/flow.mjs <输出目录>`（无头 Chromium，软件 WebGL）。

## 哪些是实测，哪些是示意

| 内容 | 性质 |
|---|---|
| 屏幕每个像素的亮度变化与色偏 | **实测**：`web/data.js` + 光学模型（`src/optics/model.ts`，由 `web/model.js` 移植，数学不变） |
| 讲解标签里的离轴角、亮度、色偏 | **实测**，按两眼中点到屏幕顶 / 中 / 底的实际角度计算 |
| 无实测的两个方位象限（左上、右下） | 用上下镜像（ψ → −ψ）补全 |
| 离轴角超过 70° | 按 70° 计，标签标“超出实测范围” |
| 人物、手机外观、灯光、背屏画面 | 示意 |

屏幕用自定义着色器：不受光照、不做色调映射、不进后期。验收：正视纯白屏时屏幕中心像素是 255 白（已验证）。

### 苹果官网模型只在本机使用

模型版权归 Apple，不能随公开仓库再分发：

- 转换流程：`usdz` → 用 `usd-core`（Pixar USD）按颜色变体展平、去掉 AR 场景里的第二台手机 → `usd2gltf` 转 GLB（`public/local/phone_<颜色>.glb`，开发页用）→ `npm run build:web` 时由 `tools/embed-apple.mjs` 写成 `web/local/iphone18pm-<颜色>.js`（base64 内嵌，双击打开也能用）。
- `scene3d/public/local/` 与 `web/local/` 已写进仓库根目录 `.gitignore`；GitHub Pages 上没有这些文件，iPhone 自动改用参数化模型。
- 重新生成：把 usdz 放到 `public/local/`，按 README 末尾“附：苹果模型转换”的命令操作。

## 人物

Quaternius Universal Base Characters（CC0）免费版的男性模型，自带含手指的骨骼。
去掉了贴图、头发、眼球和眉毛，运行时按骨骼收细四肢与肩颈、平滑肌肉与面部细节，做成普通身材的中性人台；
半透明显示时先写深度再画颜色，只显示最外层表面。来源与许可见 `CREDITS.md`。

握持：拇指搭在右边框外侧，四指从背面绕到左边框，小指托在底边。手腕绕前臂的扭转一半分给前臂（旋前 / 旋后本来就发生在前臂），场景之间过渡时手腕不会拧成“麻花”；放在桌上的手只微微弯指，摆好后检查指尖，低于桌面就把手腕抬高，手指不穿进桌面。人物透明度的变化用缓入缓出。凳子、桌子、长椅淡入淡出时画两遍（人物前后各一遍，普通半透明混合），阴影用抖动透明（VSM 模糊后看不出颗粒），旁座乘客的深度预通道也按透明度渐变；地铁小窗淡入淡出，讲解视角里换观看者时屏幕着色也平滑过渡——整个切换过程中没有“半透明 ↔ 实心”的突变（逐帧检查过相邻帧差异）。
`s3d.occlusion()`（开发页控制台）会从你的眼睛位置检查有没有身体部位挡在屏幕显示区前面，四个场景都是 0。

## 数据的已知问题

- 30° 与 60° 两组测量时屏幕状态和另外两组不同（0° 亮度高约 25–35%，白点约 5800 K 对 6600 K）。模型按每组自己的 0° 归一化来消除这个差异。
- 看到的效果也受观看者自己显示器的限制（色域、最大亮度、校准）。

## 待确认

1. 小米外观里的估计值（圆角、模组与镜头位置、按键位置）是否需要按实机再量。
2. 数据的方向约定：0° 为手机竖放；面内旋转按“30° 是顺时针”处理；+θ 表示观察者在手机右侧（上下镜像补全后，顺 / 逆时针的约定不再影响结果，但左右约定仍会影响）。
3. 小米“普通”那组数据测量时防窥确实是关闭的（现在另有一组“开启防窥”的数据）。
4. iPhone 数据标的是“GH3”屏，场景里是否就用这组。
