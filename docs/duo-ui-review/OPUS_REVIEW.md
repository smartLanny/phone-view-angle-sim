## 1. 结论

以账号为主的外屏方向是对的，而且它不是为品牌做的妥协，参考本身就是这样：
- 外屏是设置首页：标题、账号卡、分组列表、右侧轨。
- 内屏把同一份列表变成左栏，右边显示"通用"详情。

这就是分栏界面在窄屏收起、宽屏展开的常规关系。所以外屏的设计思路保留。要改的有四处：
1. 内外屏的列表不一致。
2. 外屏内容列被右轨多占了一截，显得偏窄。
3. 内屏左上角收尾太挤。
4. 内屏左下角收尾太乱。

## 2. 具体差异（从截图量出）

**外屏**

| 项目 | 参考 | 当前候选 | 判断 |
|---|---|---|---|
| 列表右缘（占屏宽） | ≈82% | ≈75% | **偏窄**，内容宽约 325 pt |
| 右轨元素中心 | ≈90% W | ≈90% W | 一致 |
| 相机 / 时间 / 状态钮 / 搜索钮（占屏高） | 7 / 13 / 19 / 92% | 7 / 14 / 19 / 93% | 一致，不动 |
| 标题、账号卡顶边 | 7% / 12% H | 6% / 12% H | 一致 |
| 账号卡高度 | ≈15% H | ≈16.5% H | 为品牌加高，可以接受 |
| 行距 | ≈7.7% H | ≈7.3% H（50 pt） | 一致，不挤 |

- 候选里列表右缘到右轨中心的空隙约占 15% 屏宽，是参考（约 8%）的两倍。
- 以内容列宽为尺度，候选外屏的头像、字号、行高比原版大 6–20%。右侧"Home–5G ›"显得紧，原因是列变窄了，不是字太大。
- 和原版比：候选把 ID 从小号浅灰放大到 16 pt，把搜索框移到右轨，这两处都对，和参考一致。
- 箭头比原版更小更浅。

**内屏横向**（有透视，数值近似）

| 项目 | 参考 | 当前候选 | 判断 |
|---|---|---|---|
| 左栏宽 | ≈33% | ≈31% | 合理，不改 |
| 左栏第一项 | 账号，顶边约 13% H，看不到大标题 | "设置"大标题，顶边约 3–4% H，贴着左上圆角；账号被挤到约 16% H | **需改** |
| 左栏行距 | ≈7.7% H | ≈7.1% H | 合理 |
| 底部搜索框 | 约 6% H，半透明 | 约 8.4% H，实心白；下面露出"通知"半行字，被圆角截断 | **需改** |
| 详情标题卡顶边 | ≈12% H，与左栏账号对齐 | ≈14% H，与左栏不对齐 | 对齐 |
| 右轨 | 约 10% W，只放时间和状态 | 约 10–11% W | 合理 |

另外三点：
- **列表重复**：左栏第一行"搜索与 Siri"，下面又有"搜索"和"Siri"，看起来像重复。参考里那一行是"Optimizing Search and Siri"，像是模拟器或测试版的临时提示，不是菜单项。
- **两屏列表不一致**：外屏是"飞行模式…个人热点 / 通知…"，内屏左栏是照抄参考的"通用 / 辅助功能 / 外观…"。同一台机器、同一个 App，折叠前后列表应该相同。参考没有无线局域网、蓝牙这类项，可能只是因为它是模拟器；真机首页应该有。
- **详情区箭头**几乎看不见。

## 3. 推荐方案 A：同一份列表，外屏为首页，内屏为左栏 + 通用

**统一列表**（两屏同序）：
- 账号
- 飞行模式、无线局域网、蓝牙、蜂窝网络、个人热点
- 通用、辅助功能、外观、主屏幕与 App 资源库、搜索、Siri、待机显示
- 通知、声音与触感、专注模式、屏幕使用时间

把"通用"组提到第二组，是为了让内屏左栏里选中的"通用"出现在搜索框上方。参考里通用组也紧跟在第一组后面。外屏的视觉写法不变，只换第二组的行名。

**外屏（闭合、竖向、右侧轨）**
- **不动的部分**：标题和相机同一行；右轨四个元素的位置；头像 64 / 名称 22 / ID 16 pt；正文 17 pt，行高 50 pt，组间距 24–28 pt。
- **列表右缘**：改到"相机孔左缘 − 16 pt"，约 82% 屏宽。左边距保持 18–20 pt，内容宽从约 325 pt 变为约 357 pt。
- **账号卡**：
  - 名称 22 pt Semibold。
  - ID 16 pt Regular，颜色加深到浅色 #6E6E73、深色 #98989D，对卡片底色对比度在 4.5:1 以上。
  - 头像与文字间距 14–16 pt。
  - 卡片高度现在约 111 pt 也行，收到约 100 pt 也行。
- **首屏内容**：0° 时能看到账号卡、第一组和通用组前 2–3 行，底部自然被裁掉，不为塞满而缩小。

**内屏横向（展开）**
- **分区**：
  - 左栏 31–33%，按固定 pt 算约 290–310 pt，白底。
  - 详情区 #F2F2F7 底、白色卡片。
  - 右轨约 10% W，只放时间和状态。
- **左栏顶部**：
  - 去掉"设置"大标题，账号作为第一项，顶边约 12% H（约 80 pt），左距 20 pt，不加卡片底。
  - 头像 56 pt，名称 20 pt Semibold，ID 15–16 pt，颜色同上。
  - 品牌就落在整块屏幕的左上起点。
- **左栏列表**：
  - 和外屏同一份、同顺序，每行只放图标和名称，不显示 Home–5G、开关这类尾值。这是我的判断，目的是降低左栏杂讯。
  - 17 pt 文字，行高 46–48 pt，图标 28 pt，组间多留约 12 pt，不画分隔线。
  - "通用"用选中胶囊，左右内缩 8 pt。
- **底部搜索**：
  - 高 40–44 pt，左右与列表对齐。
  - 底边距 12 pt 以上，离圆角弧线至少 8 pt。
  - 上方 40–48 pt 用侧栏底色渐隐，不再露出被圆角截断的残字。
- **详情区**：
  - 顶边和左栏账号对齐。
  - 标题卡：图标 44–48 pt，"通用"22–24 pt Bold，说明文字 14–15 pt、两行。
  - 下面四组卡片：关于本机 / 健康数据、照片图库 / 屏幕捕捉 / 自动填充与密码。行 17 pt / 48–50 pt，卡片间距 20–24 pt。
- **折痕**：在 50% 屏宽处，穿过详情列左侧约三分之一。文字跨过折痕对仿真有用，不需要避开。

**内屏纵向**（截图里没有，以下是我的判断）
- 顶部用约 44–54 pt 的水平状态区，代替右轨。
- 左栏保持横向时的同一 pt 宽度，详情区约 370–390 pt，相当于一部手机的宽度。
- 字号不缩放；折痕变成水平方向。

**深色**
- 侧栏和卡片 #1C1C1E，详情区底 #000。
- 选中胶囊 #3A3A3C，ID #98989D。
- 箭头沿用原版 `ui()` 深色的取值。

**替代方案 B（只在用户觉得 A 的内屏品牌不够显眼时用）**
- 外屏完全不动。
- 内屏左栏用外屏原来的列表，选中账号行，右侧显示账号详情页：头像约 88 pt 居中，名称 28 pt，下接 @bilibili，再接三组卡片。
- 好处：外屏零改动，内屏品牌最突出。
- 代价：要新画一页；偏离参考默认显示"通用"的做法；大头像落在折痕附近；品牌在同一屏出现两次，容易像宣传页。

## 4. 必改与可选

**必改**
1. 两屏统一成同一份列表，并删掉"搜索与 Siri"。
2. 外屏列表右缘从约 75% 改到约 82% 屏宽。
3. 内屏去掉左栏大标题，账号上移，与详情标题卡顶边对齐。
4. 内屏底部搜索框缩小，加渐隐，清掉被圆角截断的残行。

**低成本，建议一起改**
5. ID 灰度加深。用户点名要看清 ID，截图里它是偏浅的系统灰。
6. 箭头统一沿用原版 `ui()` 的尺寸和颜色（内屏详情区现在几乎看不见）。

**可选**
7. 外屏账号卡高度从约 111 pt 收到约 100 pt。
8. 在"原图"模式下确认详情区底色是中性的 #F2F2F7。19° 截图里偏蓝紫，可能只是仿真色偏。

**最小实施范围**：只改 `duoSettings()` / `duoUi()` 的布局常量和行数据，两份 `patterns.js` 同步改，再运行 `build:web`。不动 `duo-geometry.js`、普通手机的 `ui()`、实测数据和光学算法。

## 6. 依据的边界

- **截图能证明的**：外屏用右侧轨（相机、时间、状态、搜索）；外屏显示设置首页加账号卡；内屏横向是左栏约 33% 加"通用"详情；内屏搜索浮在左栏底部；内屏右轨只有时间和状态；内屏左栏顶部看不到大标题。
- **截图不能证明的**：内屏纵向的样子、深色效果、真机首页的顺序（参考是模拟器）、侧栏是否显示尾值、确切的 pt 值。
- **属于我的判断的**：统一列表的顺序、侧栏不显示尾值、内屏纵向方案、ID 颜色取值、搜索框上方的渐隐。
- **这些截图里没法检查的**：深色模式、折叠动画、两种渲染模式的一致性。上面清单里已经列为必须实测的项目。
