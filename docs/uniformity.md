# 屏幕均匀度：数据来源与计算方法

本页的“屏幕均匀度”用的是屏幕数据库（[smartLanny/svm-full-range-visualizer](https://github.com/smartLanny/svm-full-range-visualizer) 的 `data/uniformity/`）里的 Radiant ProMetric 二维亮度计实测。四台有数据：小米 18 Pro Max、iPhone 18 Pro Max、华为 Mate 90 Pro Max 典藏版、iPhone 17 Pro Max；每台三档：

| 档位 | 测试画面 | 亮度图 | 色温图 |
|---|---|---|---|
| 300 白场 | 300 nits 全白场 | 有 | 有 |
| 100 G20 | 100 nits 亮度档位下的 G20 灰 | 有 | 有 |
| 10 G20 | 10 nits 亮度档位下的 G20 灰 | 有 | 没有（数据库没有导出） |

iPhone Duo 没有均匀度实测；小米 18 Pro Max 的系统防窥模式没有单独测，开防窥时不计（不拿普通模式顶替）。iPhone 18 Pro Max 贴防窥膜时沿用未贴膜的实测：膜不改变面板本身，膜的影响已经在贴膜的可视角数据里。

数据库只记录了均匀度测的是哪款机型，没有记录是哪一台样机（`unit` 为空），所以不能确定 iPhone 18 Pro Max 的均匀度和可视角（GH3 屏那台）是同一台。

## 从热力图到数值

数据库里存的是热力图 PNG：数据库自己的 `pipeline/uniformity/vendor/render.py`、`export_maps.py` 把原始亮度 / 色温矩阵 1 mm 滤波后，按一条 8 段色条（`index.json` 的 `colorStops`）着色导出，色条两端对应的数值记在每张图的 `scale` 里（亮度为典型值的百分比，色温为相对典型值的 K）。原始矩阵在 NAS 上，不在仓库里。

`tools/uniformity/build.py` 按同一条色条把颜色反查回数值（每个像素取色条上最近的点；导出时浮点颜色是截断成 8 位的，先补回半个色阶），然后用数据库记录的指标逐项核对，超出容差就报错、不输出：

## 对到屏幕上

热力图的屏幕轮廓（透明度遮罩）按外接框对到 `devices.js` 的显示区。挖孔都在上方，位置与机型参数一致（例如 iPhone 18 Pro Max 灵动岛：图上中心距顶边 5.53 mm、宽 15.3 mm，参数为 5.35 mm、15.7 mm；Mate 90 三个前摄孔间距 7.2–7.3 mm，参数为 7.5 mm），横纵比例相差 0.2–1.3 %。

左右方向：数据库的 `render.py` 遇到挖孔在右边的横拍图会做一次水平翻转，原始矩阵是怎么摆的已经看不出来。小米 18 Pro Max 的可视角数据左右、上下很不对称，可以用它检验（见下一节）：按原样摆放时，热力图和“相机看屏幕边缘的视角衰减”吻合得最好，左右翻转、上下翻转、转 180° 都明显更差，所以按原样使用。

网格每台 320 行（约 0.5 mm 一格），屏幕外和挖孔里的格子取最近的有效值。数值按每张图自己的量程存成 8 位、每行左邻差分后 base64，四台各约 300 KB（网页服务器 gzip 后 160–200 KB），打开均匀度时才加载。色温另加 1.5 mm 高斯平滑：30 cm 外人眼对 1–2 mm 尺度的色度起伏不敏感，低灰阶时仪器的色温噪声却正好在这个尺度，不平滑的话色偏分布图会画出满屏的碎等值线；上表的核对用的是平滑前的值。

## 在页面里怎么算

亮度图给出每处亮度相对典型值（屏幕内部的中位数）的比 U，色温图给出相对典型色温 T0 的偏移 ΔT。色温只确定了色度沿黑体轨迹方向的变化（另一方向，偏绿 / 偏品红，仪器没有导出），所以让白点沿黑体轨迹平移：

    xy = 本机可视角数据的法线白点 + [xy_黑体(T0 + ΔT) − xy_黑体(T0)]，Y = U

再用同一份可视角数据的三基色矩阵换成三基色的驱动增益 g（三个数）。屏幕上每个像素：

    显示 = T(θ, ψ) · (g ⊙ 画面)

T(θ, ψ) 是这一点相对眼睛的离轴角下的颜色变换（原有的可视角模型）。也就是说，均匀度当作面板发光本身的明暗与色温分布，视角衰减和色偏照旧按眼睛的位置逐像素计算。

- **仿真效果**：画面乘上增益再按离轴角变换。正对时典型值为白，比典型值亮的地方在纯白画面上会被截在白。
- **分布图 → 亮度 / 色偏**：眼睛看到的白场亮度（100 % 为正对时的典型亮度）、与正对白场的色差（JNCD）。量程按当前画面里屏幕各处的最小 / 最大值取整，对比时两台共用。不计均匀度时只计视角，也能看出近距离观看时屏幕上下两端的亮度差。
- **9 点均匀**（读数行 / 对比卡片）：眼睛看到的 9 点均匀性，取点与数据库的 9 点法相同（外接框 10 % / 50 % / 90 % 处、半径为短边 4 % 的圆内平均）。各点的实测值乘上这一点按眼睛位置的视角亮度比，取最小 / 最大。正对、无限远时等于数据库的 9 点均匀性。
- 悬停读数多一行“均匀度”：这一点的实测 U 与色温偏移。

着色器的结果与 CPU 计算逐点核对过（纯白画面，正对和 25° 斜看，25 个点，差别都在 1/255 以内）。

## 测量相机的视角（待确认测量距离）

二维亮度计离屏幕只有几十厘米时，相机看屏幕边缘本身就是斜的，热力图里已经包含了这部分衰减；页面再按眼睛的位置乘一次视角衰减，就重复算了。

小米 18 Pro Max 的可视角在小角度内就掉得很快、而且左右上下不对称（正对向右 5° 只剩 92.7 %，向左 5° 还有 98.7 %），可以用来检验：拿它的可视角数据算“相机在屏幕前方 D 处时各点看到的亮度比”（光轴落点在中心附近 ±20 mm 内取最吻合的），从热力图里除掉，看剩下的起伏（对数标准差）：

| 相机距离 D | 300 白场 | 100 G20（同一相机位置） | 10 G20（同一相机位置） |
|---|---|---|---|
| 不扣除 | 2.9 % | 5.3 % | 4.0 % |
| 300 mm | 3.0 % | 5.5 % | 7.7 % |
| 400 mm | 1.8 % | 5.2 % | 6.8 % |
| 500 mm | 1.4 % | 5.1 % | 6.4 % |
| 600 mm（光轴在中心下方约 20 mm） | 1.3 % | 5.2 % | 6.1 % |
| 1000 mm | 1.8 % | 5.0 % | 4.9 % |
| 2500 mm | 2.5 % | 5.2 % | 4.2 % |

白场很吻合：D 约 50–70 cm 时起伏减少一半多，面均匀性从 85.1 % 变成约 90.8 %，两份独立测量（测角仪的可视角、二维亮度计的均匀度）在这一点上互相印证。两档 G20 却不吻合：100 G20 几乎不变，10 G20 反而变差（它本来就是上亮下暗，与相机造成的上暗下亮相反）。可能是低灰阶时的视角特性和全白不同（可视角测的是全亮的白 / 红 / 绿 / 蓝画面），也可能 G20 是另一次摆放测的，还不能下结论。另外三台在 10° 以内只掉 1–3 %，相机的影响小得多。

测量距离没有记录，所以页面**暂时不扣除**（不猜）。知道距离后，在 `tools/uniformity/camera.json` 里按机型填上（`distanceMm`、光轴落点 `offsetMm`、未开防窥的 `profile`），重新运行 `build.py` 即可：按同一台机型的可视角数据，按相机位置先除掉这部分亮度衰减和色温变化。

## 更新数据

```bash
python3 tools/uniformity/build.py --src <svm-full-range-visualizer 的 checkout>   # 生成 web/uniformity/
python3 tools/uniformity/build.py --check                                         # 核对是否最新
```

依赖 numpy、scipy、pillow（与数据库的均匀度脚本相同）和 node。`web/uniformity/index.js` 记录了源仓库的分支、提交号和 `index.json` 的 sha256；重新生成后把 `index.html` 里 `uniformity/index.js?v=` 的版本号改一下。
